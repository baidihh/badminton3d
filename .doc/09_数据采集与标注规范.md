# 数据采集与标注规范

## 1. 目标

积累“真实手机姿态 → 挥拍动作 → 服务端击球结果”的样本，用于：

- 校准默认阈值（挥拍角速度、力度映射、球路判定边界）
- 分析真实玩家的握持角度、挥拍幅度、速度分布
- 后续训练姿态分类模型（可选）

## 2. 目录

```text
data/
  sessions/   每次手柄连接一份 JSONL（已忽略，不进 Git）
  labels/     人工标注结果（已忽略）
  tools/      汇总脚本
```

原始数据只存本地，不提交仓库，避免隐私与体积问题。

## 3. 采集开关

| 方式 | 说明 |
| --- | --- |
| 默认 | 开启，手柄加入场地即开始记录 |
| 环境变量 | `RECORD=0 npm start` 关闭；`RECORD_POSE_HZ=30` 调整姿态采样率 |
| 存储位置 | `RECORD_DIR=/path` 自定义根目录 |
| 运行中 | `GET /api/rec` 查看状态；`/api/rec?on=0` / `?on=1` 关闭或开启 |

每个手柄独立一个文件，文件名为 `时间_场地_IP.jsonl`，断线自动收尾。

## 4. 记录内容

每行一个 JSON 对象，`t` 为该会话开始的毫秒数。

| type | 触发 | 主要字段 |
| --- | --- | --- |
| `session` | 手柄加入场地 | `slot, ip, hand, ua, viewport, level, mode, lan` |
| `pose` | 姿态上报（默认 20 Hz） | `q`（四元数）, `az`/`el`（弧度）, `om`（角速度 °/s）, `hand` |
| `swing` | 手机判定挥拍 | `swingId, power, dir, peak, lift, shot, dropHold, az, el, om` |
| `hit` | 服务端确认击球 | `swingId, grade, power, shot, q, contact, ball, target{tx,tz,T}` |
| `miss` | 挥拍窗口内未碰到球 | `swingId, ball` |
| `point` | 一方得分 | `winner, reason, score, rally` |
| `session_end` | 断线/关闭 | `reason` |

`swingId` 是手机挥拍与服务端击球结果的关联键：`swing` 与 `hit` / `miss` 通过它配对。

## 5. 标注来源

- **球路标签**：`hit.shot` 为服务端最终采用的球路（含低点杀球降级结果），优先于 `swing.shot`。
- **质量标签**：`hit.grade`（`perfect` / `good` / `edge`）与 `hit.q`（甜区质量 0–1）。
- **时机标签**：有 `hit` 即命中，有 `miss` 即漏击。
- **结果标签**：`point.winner` 结合 `hit.slot` 判断这一拍是否直接得分。
- **姿态特征**：`hit` 前最近的若干条 `pose`，可提取起拍角、扫角、峰值角速度。

人工修正写入 `data/labels/<会话名>.json`，按 `swingId` 覆盖自动标签。

## 6. 引导标注模式

手机打开 `https://<IP>:3543/ctrl?label=1`，完成校准后会自动进入标注：

- 屏幕顶部显示「请打：高远球 / 吊球 / 杀球」，共 12 拍（3 种 × 4 轮，每轮随机顺序）。
- 每挥一拍自动记录 `requested`（要求球路）与手机判定 `shot`，面板上的进度点显示是否一致。
- 数据仍写入 `data/sessions/`，`swing` 行增加 `requested` 与 `match` 字段。
- 12 拍完成后显示一致数，页面保持可继续查看。

对照统计：

```bash
npm run data:summary
```

会额外输出「标注对照」：要求球路 → 实际判定的混淆矩阵、手机判定一致率、服务端最终球路一致率。

## 7. 汇总分析

```bash
node data/tools/summarize.mjs          # 可读报表
node data/tools/summarize.mjs --json   # 机器可读
node data/tools/summarize.mjs --dir data/sessions
```

输出内容：

- 会话数、姿态样本数、挥拍数、命中率、漏击数
- 持拍手分布、评价分布
- 按球路统计：挥拍数、命中率、平均力量、峰值角速度（均值/最大）、仰角与方位范围、平均飞行时间

## 7. 使用建议

- 至少收集 3 种持拍手、不同身高的 5 名玩家，各打 20 拍以上，样本才有代表性。
- 调整力度映射或挥拍阈值前，先对比 `swing.peak` 与 `hit.grade` 的分布，避免只按单人数据调参。
- 分析杀球判定时，用 `swing.el` 的起拍值与 `hit.contact` 联合看，低点样本要单独统计。
- 数据只含 IP、UA、屏幕尺寸与运动数据，不含姓名与账号；对外分享前先脱敏 IP。
