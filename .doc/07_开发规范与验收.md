# 开发规范与验收

## 1. 代码规范

- 前后端均为 ES Module，无打包步骤，改完直接刷新页面。
- 缩进 2 空格；分号保留；字符串优先单引号（JSON/HTML 内除外）。
- 大段逻辑用中文分区注释说明“做什么/为什么”，不要逐行注释。
- 不提交调试钩子（如 `window.__debug`）、临时测试页、测试脚本。
- 高频循环内复用 Vector3/Quaternion，避免每帧新建对象。
- 服务端保持 60 Hz 预算：新增逻辑避免 O(n²) 遍历与每步分配大对象。

## 2. 资源与目录

| 规则 | 说明 |
| --- | --- |
| `node_modules/` | 不提交 |
| `certs/` | 自签证书，不提交 |
| `shots/` | 测试截图，已忽略 |
| `宣发/` | 宣传素材，保留本地，未跟踪 |
| `models/Xbot.glb` | 运行必需，已提交；确认 Mixamo 授权后再公开分发 |

## 3. Git 规范

- 提交主题用中文、单行、不超过 70 字，说明“做了什么”。
- 正文补充“为什么/影响范围”，1–3 句话即可。
- 一次提交只做一类事情：功能、修复、文档分开。
- 禁止提交密钥、证书、个人隐私截图。
- 不强制推送主分支；推送前先确认远端状态。

## 4. 验收清单

| 编号 | 检查项 | 预期结果 |
| --- | --- | --- |
| 1 | 打开大屏与手机页 | 大屏 200、手机 HTTPS 可打开，无控制台报错 |
| 2 | 手机权限与校准 | 2 秒采样完成，可点「确定初始姿态」 |
| 3 | 初始拍位 | 手机放平拍子低、抬高拍子高，不再固定高举 |
| 4 | 玩家发球 | 球停在发球点，挥拍后过网进入回合 |
| 5 | 电脑发球 | 电脑拿到发球权后 1 秒左右主动发球，不卡死 |
| 6 | 三种球路 | 高远/吊/杀均能打出，颜色、标签、音效不同 |
| 7 | 低点杀球 | 触球低于 1.75 m 自动变高远 |
| 8 | 手臂限制 | 球在身后时手臂停在体侧，不绕到背后 |
| 9 | 步法 | 跑动有交替迈步，近球有弓步与重心下沉 |
| 10 | 左手持拍 | 手机切换后大屏人物换左手，吊球键换边 |
| 11 | 姿态重置 | 单击立即生效，文字立刻变为“姿态已重置” |
| 12 | 全屏/息屏 | 全屏可进可退；息屏黑屏锁触，长按可唤醒 |
| 13 | 难度 | 三档可选、立即生效、刷新后记住 |
| 14 | 场地接管 | 手机刷新后同 IP 接管原场地，不提示场地已满 |
| 15 | 小屏适配 | 375×667 下按钮不重叠、圆环不压吊球键 |

## 5. 发布步骤

1. 修改 `server.js` 后重启服务；仅改前端则手机/大屏刷新即可。
2. 打开 `/api/stats` 确认服务、场地、比分正常。
3. 按验收清单抽查关键项。
4. 提交并推送：`git add <具体文件>` → `git commit` → `git push`。
