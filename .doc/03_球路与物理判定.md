# 球路与物理判定

## 1. 三种球路

| 球路 | 手机端判定 | 设计意图 |
| --- | --- | --- |
| 高远球 `clear` | 向上挥：`elMax - elStart > 0.15`，且未达到杀球的举高条件 | 送到后场，拖时间 |
| 吊球 `drop` | 按住「吊球」键再挥 | 轻吊网前，改变节奏 |
| 杀球 `smash` | 举高发力：仰角峰值 > 22°（0.38 rad）且峰值角速度 > `max(380, 阈值×1.2)`；16°–22° 这条临界带额外要求 > `max(480, 阈值×1.5)` | 高点下压，压迫对手 |

- 判定顺序：吊球（显式修饰）→ 举高发力（杀球）→ 向上挥（高远）→ 兜底高远。
- 阈值来自真实标注数据：12 拍样本里，高远仰角峰值 ≤ 8°，杀球仰角峰值 28°–44°，用 16° 可完全分开。
- 低点（触球高度 < 1.75 m）的杀球自动降级为高远球。

## 2. 击球质量

- 距离质量 `q = 1 - d / 0.98`，`d` 为球与拍面中心距离。
- 评价：`perfect`（q > 0.72）、`good`（q > 0.42）、`edge`（其余）。
- 有效力量 `effPower = power × (0.74 + q × 0.34)`。
- 横向落点由**挥拍方向**决定，见 2.1；越不准随机偏差越大。

### 2.1 横向落点：按挥拍方向延伸

击球瞬间手机指向的方位角 `az`（控制系，`+` = 持拍手一侧，来自角速度峰值那一刻）决定横向落点：

```
sideSign = 本方在左半场 ? -1 : +1     // 把"我的左右"换算成世界 x
reach    = max(1.6, |tz - 触球 z|)    // 触球点到落点的飞行距离
azUse    = 死区(az, 4°) 后做 soft-sat: tanh(azUse × 1.15) × 0.9
tx       = 击球者 x + sideSign × tan(azUse) × reach
tx       = clamp(tx + 随机误差 × (1 - q), -2.45, 2.45)
```

手感修正（体感游戏通用的"意图一致性"做法）：

| 修正 | 作用 |
| --- | --- |
| 死区 4° | 手腕轻微抖动不改落点，避免"手一抖球跑半米" |
| 软饱和 `tanh` | 大角度不再线性放大，防止一下顶到边线；0–23° 覆盖中路到边线 |
| 落点辅助 ±2.45 m | 始终留 0.45 m 边线余量，不把球判死在线上 |

效果（以站在右半场、右手指拍为例）：

| 挥拍方向 | az | 落点 |
| --- | --- | --- |
| 由右向左挥（跨身） | 负 | 对角，飞到对方左场 |
| 略向左 / 略向右 | ≈ 0 | 中路 |
| 由右向前（顺边线） | 正 | 直线，压对方右边线 |

- 为什么用射线而不是固定三档：`tan(az) × reach` 就是真实羽毛球里"拍面角度 × 飞行距离"的横向位移，同一角度在近网和底线产生的偏移量不同，符合真实手感。
- 左右镜像：`sideSign` 由半场决定，所以左半场玩家做同样的"向场内挥"动作，也是同样对角球。
- 落点超出边线时夹在 ±2.75 m（边线内侧），相当于"瞄边线"，不会直接出界。
- 电脑（AI）不受手机方位角影响，直接用 `opts.tx` 指定落点。

## 3. 弹道模型

- 重力 `G = 9.8`，**二次空气阻力** `a = -DRAG·|v|·v`，`DRAG = 0.11`，末端速度约 9.4 m/s。
- 物理步进用 8 ms 子步长，避免高速穿模与数值发散。
- 击球时用牛顿迭代反求初速度，保证在给定飞行时间内落到目标点（误差 < 2 cm），不用近似公式。
- 触球高度参与计算：`contact = clamp((球高 - 1.3) / 1.3, 0, 1)`。

| 球路 | 目标深度（相对击球方） | 飞行时间 |
| --- | --- | --- |
| 高远 | `2.0 + effPower × 3.6`，限制 1.4–6.2 m | `1.52 - effPower × 0.46 + 抬拍 + 接触高度修正` |
| 吊球 | `1.5 + 0.6 × effPower × 1.7 + contact × 0.3`，限制 1.5–3.4 m | `1.34 + 抬拍修正 - 期望力量修正` |
| 杀球 | `3.0 + effPower × 1.8 + contact × 0.7`，限制 3.0–5.4 m | `1.03 - effPower × 0.30 - contact × 0.07`，限制 0.70–1.0 s |

典型轨迹：高远顶点约 4.3 m、过网约 4 m；吊球顶点约 3.5 m、过网约 2.9 m；杀球顶点约 2.5 m、过网约 2.3 m。

- 过网保护：模拟球到网面（z=0）的高度，不足 1.65 m 时延长飞行时间重算（最多 10 次），避免压网。
- 触网：球撞在网带上后几乎垂直落回击球方半场，判定失分。
- 落地：球落地即判定该半场失分；发球连续 3 次失误自动发球。

## 4. 碰撞与判定

- **扫掠碰撞**：用这一帧球走过的线段到拍心的最近距离判定，避免高速球在两帧之间“穿过”球拍。
- 球拍可及半径 `HIT_R = 0.98 m`；触球高度限制 0.06–3.7 m（过低/过高打不到）。
- 只能击打本方半场的球（`z` 侧判定）。
- 甜区质量 `q = 1 - d / HIT_R`，`d` 为扫掠最近距离：`perfect`（q > 0.72）、`good`（q > 0.42）、`edge`（其余）。

## 5. 时间戳回溯（延迟补偿）

借鉴 Source / CS2 的 lag compensation（`Command Execution Time = 当前服务端时间 - 网络延迟 - 客户端插值延迟`）：

- 服务端保留最近 **1 秒**的球轨迹（60 Hz 采样，线性插值取任意时刻位置）。
- 手机端记录**角速度峰值**的本地时刻，随挥拍包发送：
  - `ageMs`：峰值 → 发出这一包的耗时（挥拍检测本身的延迟）
  - `rttMs`：应用层 ping 实测的往返延迟，单程取一半
- 服务端把判定回退 `ageMs + rttMs / 2`，**上限 250 ms**，用那一刻的球位做命中判定。
- 回溯命中只判一次；没中再回落到实时扫掠，保留原有 0.3 s 容错窗口（挥早了也能捞回来）。
- **只回溯球，不回溯人**——与 Source "只倒放其他玩家"同一思路，人物位置在 250 ms 内变化可以忽略。
- 落点与球路用回溯位置的触球高度计算，但发射位置仍用当前球位，避免画面出现"球倒退"。

## 6. 漏击原因

服务端在挥拍窗口结束时用挥拍瞬间的球位判定原因，手机端显示对应提示：

| reason | 条件 | 手机提示 |
| --- | --- | --- |
| `far` | 球距拍心 > 2.3 m | 够不到 · 往球的落点走一步 |
| `high` | 球高 > 2.9 m | 球还高 · 等它下落再挥 |
| `late` | 球已过身 | 慢了一点 · 再早一点 |
| `early` | 其余 | 早了一点 · 到身边再挥 |
