# 2026-10-29 体感羽毛球改进

## 本轮实现

- 自动跑位预测未来 2.5 秒的可触球位置，允许在球过网前启动拦截。
- 有效挥拍产生 0.38 秒移动恢复，最低目标速度为正常值的 55%，随后逐渐恢复。
- 连续挥拍累计恢复时间，上限 0.75 秒；命中后缩短至 0.12 秒。服务端挥拍间隔 0.22 秒。
- 手机显示收拍恢复提示；可击提示改用实际拍心和 0.98 米判定半径。
- 出界由最后击球者承担；网平面和落地位置使用帧内插值。
- 历史补偿配对历史球位和历史拍心，命中从历史触球点发射；每次击球/发球清空旧历史。当前采用触球点校正，不是完整世界回滚重演，较高延迟下仍可能看见位置修正。
- 预测弹道与实时模拟共享积分器，求解后重新检查过网高度并返回落点误差。
- 网络入口校验消息形状、关键数值和频率；手柄输入校验位置所有权；模式和难度由大屏控制，已入场玩家可以重开。
- 切换、接管、断线清理位置和反馈房间；重复入场保持原位置。
- 漏击原因进入采样记录；记录流错误不会直接成为未捕获事件。
- 大屏对局位置按真实时间更新，移除本地时间缩放造成的球位漂移。

## 验证

执行 `npm test`。定向回归场景覆盖：正常接到斜线球、乱挥一次仍可到达、乱挥两次错过接球范围；无随机强制漏接逻辑。
另用真实 Socket.IO WebSocket 协议完成启动、手柄入场、无效消息和断线释放检查。

## 后续范围

- 恢复参数需要真实手机与不同水平玩家调试，自动测试不代表实机手感已经定稿。
- 大屏注册是局域网角色约定，没有加入配对密钥或公网鉴权。
- 网络状态插值缓冲、设备延迟标定、跨设备传感器识别、完整世界回滚尚未实现。
- AI 的随机失误尚未改为完整的反应/跑位失误；弱回球、进攻机会和辅助强度分档继续保留为下一阶段玩法工作。
- Game 职责拆分和可设种子的整局重放尚未实施；本轮优先修复规则并统一物理计算来源。

## 第二轮：实机反馈后的输入与人物修正

分析本次采样片段：82 次有效挥拍，52 次命中，30 次漏击；52 个落点中 34 个被夹到边线附近。补偿量中位数 140.8ms，最大 250ms；这不是纯网络 RTT，包含挥拍检测等待时间。

- 取消绝对方位角乘飞行距离的落点映射，改用单次挥拍内的世界竖轴角速度积分，8° 死区、45° 左右达到最大横向意图。直接映射到对方场地 ±2.25m，不受站位影响。
- 普通直上直下挥拍默认中路。左右反转按钮仍可用。雷达和方向文案使用同一意图信号。
- 峰值后回落 45ms 可结束识别，最长识别窗口由 300ms 缩到 180ms；仍需下一轮实机确认误触发率和新延迟分布。
- 手机姿态采用按时间平滑，静止时抑制小抖动，删除用于显示姿态的前半球硬投影。重新校准清除方向历史。
- 人物使用已有骨架与动画，添加程序化运动员形体（衣服、短裤、鞋、头部），隐藏原机器人蒙皮；这是简洁风格，并非写实资产或动作捕捉。
- 手臂由拍面中心和实际拍杆长度反求腕部，肘腕独立求解；击球事件携带触球点和阶段时间，显示准备、引拍、触球、收拍。
- 限制头部转动，不再把头顶子骨直接瞄向球。减少身体位置平滑造成的拖移；两脚避免无条件同时迈步。
- `test/sensor.test.js` 覆盖左右反向、绝对朝向变化、纯竖向挥拍；`test/rig.test.js` 使用真实 GLB 骨架检查左右手触球误差和骨骼数值稳定性。
- 离线渲染四阶段骨骼预览进行检查；当前 in-app browser 读取超时，尚未完成浏览器画面和真实手机的新一轮验收。

仍需迭代：超出解剖可及范围时，显示端会限制伸展，服务端现有容错球体仍可能接受较远触球；这部分要继续统一。未加入人体刚体碰撞、拍面冲量或写实运动员资产。
